# برگه‌ی تمرین‌های دوره

## ایجنت‌های هوش مصنوعی؛ از شناخت تا استفاده‌ی سنجیده

این برگه برای تمرین و یادداشت‌برداری است. پاسخ‌دادن به پرسش‌های شخصی یا توضیح‌دادن درباره‌ی محل کار و زندگی لازم نیست. در همه‌ی فعالیت‌ها از متن ساختگی یا اطلاعات عمومی استفاده کنید؛ اطلاعاتی را که نمی‌خواهید با یک سرویس در میان بگذارید، در اختیار آن نگذارید.

---

## اصطلاحات ضروری

| فارسی | انگلیسی | معنی ساده |
|---|---|---|
| هوش مصنوعی | Artificial Intelligence (AI) | برنامه‌هایی که کارهایی مانند پاسخ‌دادن، فهم متن یا ساختن تصویر انجام می‌دهند. |
| مدل زبانی بزرگ | Large Language Model (LLM) | برنامه‌ای که از متن‌های بسیار، الگوهای زبان را یاد می‌گیرد و بر پایه‌ی آن‌ها پاسخ می‌سازد. |
| چت‌بات | Chatbot | برنامه‌ای که با آن گفت‌وگو می‌کنیم و از آن سؤال می‌پرسیم. |
| ایجنت هوش مصنوعی | AI Agent | برنامه‌ای که می‌تواند چند گام را برای انجام یک کار دنبال کند و گاهی از ابزارها کمک بگیرد. |
| درخواست یا دستور | Prompt | چیزی که به هوش مصنوعی می‌نویسیم تا بداند چه کاری انجام دهد. |
| ابزار | Tool | قابلیتی مانند جست‌وجوی وب یا خواندن فایل که ایجنت ممکن است از آن استفاده کند. |
| حافظه | Memory | اطلاعاتی که برنامه برای ادامه‌ی کار نگه می‌دارد؛ شیوه‌ی نگهداری در هر سرویس فرق دارد. |
| رابط برنامه‌نویسی | Application Programming Interface (API) | راهی که دو برنامه با آن اطلاعات ردوبدل می‌کنند. |
| نظارت انسانی | Human-in-the-Loop (HITL) | یعنی انسان بخش‌های مهم کار را بررسی یا تأیید می‌کند. |
| زمینه | Context | توضیح کوتاهی درباره‌ی موضوع و خواننده‌ی متن. |
| کار درخواستی | Task | کاری که از ابزار می‌خواهیم انجام دهد. |
| محدودیت | Constraint | چیزی که ابزار نباید تغییر دهد یا انجام دهد. |
| قالب پاسخ | Output Format | شکلی که می‌خواهیم جواب داشته باشد؛ مثلاً یک بند، فهرست یا جدول. |
| سرویس ابری | Cloud Service | برنامه‌ای که از راه اینترنت کار می‌کند و برای پردازش، متن را به سرویس می‌فرستد. |
| خودمیزبان | Self-hosted | برنامه‌ای که خود فرد یا گروه آن را نصب و نگهداری می‌کند. |
| متن‌باز | Open Source | برنامه‌ای که کد آن برای دیدن یا تغییرکردن در دسترس است؛ این به‌تنهایی امنیت را تضمین نمی‌کند. |
| سازنده‌ی ایجنت | Agent Builder | ابزاری برای ساختن ایجنت و وصل‌کردن آن به فایل‌ها یا سرویس‌های دیگر. |
| دسته‌بندی داده | Data Classification | جداکردن اطلاعات بر پایه‌ی میزان حساسیت و خطری که افشای آن‌ها دارد. |
| اطلاعات شناسایی‌کننده | Personally Identifiable Information (PII) | اطلاعاتی مثل نام، نشانی یا شماره که می‌تواند یک فرد را مشخص کند. |
| بی‌نام‌سازی | Anonymization | برداشتن نشانه‌هایی که می‌توانند فرد را شناسایی کنند؛ ترکیب چند جزئیات هم ممکن است هویت را آشکار کند. |
| جایگزینی نام با کد | Pseudonymization | عوض‌کردن نام با یک کد؛ اگر کلید کدها باقی بماند، فرد هنوز قابل شناسایی است. |
| اطلاعات جانبی | Metadata | اطلاعاتی درباره‌ی فایل یا اتصال، مثل زمان، اندازه یا فرستنده. |
| رمزگذاری | Encryption | تبدیل اطلاعات به شکلی که بدون کلید مناسب خوانده نشود. |
| کمترین دسترسی | Least Privilege | دادن فقط همان دسترسی‌هایی که برای انجام کار لازم‌اند. |
| تزریق دستور | Prompt Injection | تلاش یک متن یا صفحه برای واداشتن ایجنت به نادیده‌گرفتن درخواست اصلی. |
| توهم هوش مصنوعی | AI Hallucination | وقتی هوش مصنوعی چیزی نادرست یا ساختگی را با اطمینان بیان می‌کند. |
| جعل عمیق | Deepfake | تصویر، صدا یا ویدیوی ساختگی که شبیه فردی واقعی به نظر می‌رسد. |
| بررسی درستی خبر | Fact-checking | سنجیدن ادعاها با منبع اصلی یا منبع معتبر دیگر. |
| فیشینگ | Phishing | پیام، تماس یا صفحه‌ی جعلی برای گرفتن رمز، کد یا اطلاعات دیگر. |
| تأیید هویت دومرحله‌ای | Two-Factor Authentication (2FA) | ورود به حساب با رمز و یک راه تأیید دیگر. |
| کد بازیابی | Recovery Code | کدی برای ورود دوباره به حساب وقتی روش معمول تأیید در دسترس نیست. |
| دستور پایه‌ی ایجنت | System Prompt | راهنماهای اصلی‌ای که به ایجنت می‌گویند چطور پاسخ دهد یا کار کند. |
| پاسخ به رخداد | Incident Response | کارهایی که پس از خطا یا افشای ناخواسته انجام می‌دهیم تا مشکل را مهار و بررسی کنیم. |
| افشای ناخواسته‌ی داده | Data Breach | وقتی اطلاعاتی بدون اجازه یا برخلاف انتظار در دسترس دیگران قرار می‌گیرد. |
| آزمون | Testing | امتحان‌کردن ابزار با پرسش‌ها و نمونه‌های گوناگون برای پیدا کردن خطا. |
| پیگیری رفتار | Monitoring | زیرنظرگرفتن عملکرد ابزار پس از راه‌اندازی و توجه به خطاهای تازه. |
| کارت مشخصات ایجنت | Agent Card | یادداشتی که کاربرد، دسترسی‌ها، مسئول بازبینی و نتیجه‌ی آزمون ایجنت را ثبت می‌کند. |
| فهرست بررسی | Checklist | فهرستی از پرسش‌ها یا کارها برای اطمینان از جا نیفتادن نکته‌ای مهم. |

## ماژول ۱ — ایجنت چیست؟

### تمرین دونفره
یک کار روزمره را انتخاب کنید؛ مثلاً آماده‌کردن پیش‌نویس خبرنامه از چند یادداشت عمومی. کدام بخش را می‌شود به ابزار سپرد؟ کدام بخش به قضاوت انسان نیاز دارد؟

### نقشه‌ی کار
برای نمونه‌ی «خلاصه‌کردن یک متن عمومی»، مسیر را بنویسید:

**درخواست → بررسی متن → ساخت پیش‌نویس → بازبینی → تأیید**

در کدام گام ممکن است ایجنت اشتباه کند؟ چه کسی باید پیش از گام بعدی آن را بررسی کند؟

### یادداشت فردی
«برای من، ایجنت زمانی مفید است که _________________________________.»

## ماژول ۲ — انتخاب کار و نوشتن درخواست

### از کار کلی به کار روشن
درخواست مبهم زیر را دقیق‌تر کنید:

> «این خبر را برای انتشار آماده کن.»

درخواست را با چهار بخش روشن‌تر کنید:

1. **زمینه (Context):** متن درباره‌ی چیست و چه کسی آن را می‌خواند؟
2. **کار درخواستی (Task):** دقیقاً چه کاری باید انجام شود؟
3. **محدودیت‌ها (Constraints):** چه چیزهایی نباید تغییر کنند یا ساخته شوند؟
4. **قالب پاسخ (Output Format):** جواب را به چه شکل می‌خواهید؛ مثلاً خلاصه، ترجمه یا چند پیشنهاد؟

برای نمونه: «این خبر را برای خواننده‌ای که موضوع را تازه می‌شناسد، در یک بند خلاصه کن. عدد یا نقل‌قول تازه نساز. پاسخ را در سه نکته بنویس.»

### بازنویسی دونفره
درخواست خود را با هم‌گروهی عوض کنید. آیا او می‌فهمد چه کاری باید انجام شود و چه کاری نباید انجام شود؟ یک بخش مبهم را روشن‌تر کنید.

### گفت‌وگوی گروهی
چه کارهایی را بهتر است به ایجنت نسپاریم؟ برای نمونه، تصمیم‌هایی که نتیجه‌ی مهمی برای کسی دارند یا باید با منبع اصلی بررسی شوند.

---

## ماژول ۳ — انتخاب ابزار

در این بخش، سرویس ابری (Cloud Service) از راه اینترنت کار می‌کند. ابزار متن‌باز (Open Source) کدی دارد که می‌توان آن را دید یا تغییر داد؛ اما این به‌تنهایی به معنی امن‌بودن آن نیست.

### مقایسه‌ی سناریو
فرض کنید قرار است یک خبر عمومی را خلاصه و به سه زبان ترجمه کنید. برای انتخاب روش یا ابزار، این پرسش‌ها را بررسی کنید:

| پرسش | یادداشت گروه |
|---|---|
| آیا ابزار زبان‌ها و قالب مورد نیاز را پشتیبانی می‌کند؟ | |
| آیا می‌توان بدون ساخت حساب یا افزودن دسترسی‌های اضافی کار را انجام داد؟ | |
| آیا شرایط استفاده و نگهداری داده برای ما روشن است؟ | |
| آیا هزینه، محدودیت یا نیاز به اینترنت دارد؟ | |
| آیا راه دستی یا ابزار جایگزین در دسترس است؟ | |

### تصمیم فردی
برای هر دسته بنویسید چه کاری می‌کنید. اگر پاسخ را نمی‌دانید، «بررسی شود» بنویسید:

- متن عمومی: ______________________________________
- اطلاعاتی که ممکن است به فردی مربوط باشد: ___________
- اطلاعات محرمانه یا حساس: __________________________

### جمع‌بندی
کدام معیار در انتخاب ابزار برای شما مهم‌تر بود؟ آیا اطلاعات کافی برای تصمیم‌گیری دارید؟

## ماژول ۴ — داده و حریم خصوصی

**کم‌کردن داده (Data Minimization)** یعنی فقط اطلاعات لازم را نگه داریم. **بی‌نام‌سازی (Anonymization)** یعنی برداشتن نشانه‌های هویتی؛ بااین‌حال چند جزئیات کنار هم گاهی هنوز می‌توانند فرد را بشناسانند.

### چه چیزی را به اشتراک نگذاریم؟
برای یک خبر عمومیِ ساختگی، سه دسته درست کنید:

- **لازم برای کار:** اطلاعاتی که ایجنت برای انجام همین درخواست نیاز دارد.
- **غیرلازم:** اطلاعاتی که می‌توان پیش از استفاده حذف کرد.
- **حساس:** اطلاعاتی که نباید در این تمرین وارد ابزار شود.

### کم‌کردن اطلاعات متن
در متن نمونه، نشانی، شماره تماس، نام غیرضروری و جزئیاتی را که می‌تواند فردی را بشناساند پیدا کنید. آن‌ها را بردارید و ببینید آیا متن هنوز برای ترجمه و خلاصه‌کردن کافی است.

### نقشه‌ی گردش داده
پیش از فرستادن متن به هر سرویس، این مسیر را روی کاغذ رسم کنید:

**متن از کجا می‌آید؟ → چه کسی یا سرویسی آن را می‌بیند؟ → کجا ذخیره می‌شود؟ → چه کسی خروجی را بازبینی می‌کند؟**

اگر بخشی از مسیر معلوم نیست، آن را با علامت سؤال مشخص کنید و پیش از استفاده‌ی واقعی درباره‌اش بررسی کنید.

---

## ماژول ۵ — خطاها و درخواست‌های گمراه‌کننده

**تزریق دستور (Prompt Injection)** یعنی متن یک صفحه یا فایل تلاش کند ایجنت را وادار کند از خواسته‌ی شما سرپیچی کند.

### آزمون متن
یک متن ساختگی را به ایجنت بدهید که درون آن جمله‌ای نامربوط یا دستور گمراه‌کننده آمده است. بررسی کنید آیا ایجنت آن را به‌اشتباه به‌عنوان دستور اجرا می‌کند یا محتوای متن را درست خلاصه می‌کند.

### چه چیزی را باور کنیم؟
پاسخی را که شامل ادعا، عدد یا نام است با متن اصلی مقایسه کنید. موارد تأییدشده، تغییرکرده و نامطمئن را جداگانه بنویسید.

### تصمیم در موقعیت نامعمول
فرض کنید ابزار می‌خواهد کاری بیرون از گفت‌وگو انجام دهد؛ مثلاً ایمیل بفرستد یا متن را منتشر کند. چه کسی اجازه می‌دهد؟ چه چیزی باید پیش از آن بازبینی شود؟

---

## ماژول ۶ — عادت‌های امن در کار روزمره

**مدیر رمز (Password Manager)** برنامه‌ای است که رمزهای جداگانه‌ی حساب‌ها را در یک جای قفل‌شده نگه می‌دارد. **تأیید هویت دومرحله‌ای (Two-Factor Authentication یا 2FA)** یعنی برای ورود، علاوه بر رمز، یک راه تأیید دیگر هم لازم است.

### بررسی حساب‌ها بدون نوشتن رمز
بدون یادداشت‌کردن نام کاربری یا رمز، بررسی کنید آیا برای حساب‌های مهم رمزهای تکراری دارید و آیا امکان فعال‌کردن تأیید دومرحله‌ای وجود دارد. از رمزها عکس نگیرید و آن‌ها را در این برگه ننویسید.

### اگر دستگاه در دسترس نبود
یک برنامه‌ی کلی بنویسید: چه کسی را خبر می‌کنید، از کدام دستگاه یا حساب اقدام می‌کنید و چه دسترسی‌هایی را باید بررسی یا لغو کنید؟ اطلاعات واقعی حساب‌ها را درج نکنید.

### پیام مشکوک
برای هر پیام نمونه مشخص کنید چه چیزی را پیش از کلیک یا پاسخ‌دادن بررسی می‌کنید. فوریت، درخواست اطلاعات، پیوند ناشناس و تغییر ناگهانی روش تماس از نشانه‌هایی هستند که باید مکث و بررسی را برانگیزند.

---

## ماژول ۷ — کارگاه ساخت و آزمودن

**دستور پایه (System Prompt)** راهنمای اصلی رفتار دستیار است. با **آزمون (Testing)** یعنی امتحان‌کردن آن با پرسش‌های گوناگون، خطاهایش را پیدا می‌کنیم.

### طراحی نمونه
با یک راهنمای ساختگی یا اطلاعات عمومی، برای یک کار محدود دستیار طراحی کنید؛ مثلاً پاسخ‌دادن به پرسش‌های پرتکرار از روی یک راهنمای بازدید.

ثبت کنید:
- کار مشخص ایجنت چیست؟
- از کدام متن استفاده می‌کند؟
- چه کاری اجازه ندارد انجام دهد؟
- چه کسی پاسخ را بازبینی می‌کند؟

### تبادل آزمون
گروه دیگری این سه پرسش را امتحان کند:
1. پرسشی که پاسخ آن در راهنما هست.
2. پرسشی که پاسخ آن در راهنما نیست.
3. پرسشی که می‌خواهد ایجنت اطلاعات فردی را بازگو کند یا اقدامی بیرونی انجام دهد.

### بازتاب
یک پاسخ خوب، یک خطا یا مورد نامطمئن، و یک اصلاح پیشنهادی را ثبت کنید. اگر پاسخ در راهنما نبود، ایجنت چه باید بگوید؟

> اگر از ابزار برخط استفاده می‌کنید، پیش از آن تنظیمات و شرایط سرویس را بررسی کنید و فقط اطلاعات عمومی یا ساختگی به کار ببرید. تمرین را می‌توان بدون اینترنت و با نقش‌آفرینی انجام داد.

---

## ماژول ۸ — جمع‌بندی و قدم بعدی

### آیا آماده‌ایم؟
برای هر مورد یکی از این وضعیت‌ها را انتخاب کنید: **روشن است**، **نیاز به بررسی دارد**، **فعلاً انجام نمی‌دهیم**.

- کار مورد نظر و دلیل استفاده از ایجنت را می‌توانم توضیح دهم.
- می‌دانم چه داده‌ای وارد ابزار می‌شود و چه چیزی را باید حذف کنم.
- می‌دانم چه کسی خروجی را پیش از استفاده بررسی می‌کند.
- می‌دانم اگر پاسخ نامطمئن یا اقدام نامنتظر دیدم چه کنم.
- برای زمان قطع اینترنت یا در دسترس نبودن ابزار، راه دیگری دارم.

### سه عادت عملی
یک تا سه کار کوچک انتخاب کنید. برای هر کدام بنویسید چه کسی پیگیری می‌کند و از کجا معلوم می‌شود انجام شده است.
